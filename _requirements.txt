# CloudAgent — MVP Requirements

Build a Cloud Agent Platform: users submit a natural-language task (e.g. "read
this repo, find all TODOs, generate a report"), and the platform launches an
autonomous agent that executes in an isolated cloud environment — calling an LLM
to reason, calling tools (run commands, read/write files), iterating until done,
then returning the result. Think Claude Code Cloud / Devin / OpenAI Agents.

## Four pillars (demo must cover all four)

| Pillar | MVP must show |
|--------|---------------|
| Agent orchestration | Submit task → queue/worker → status queryable (UI or API) |
| Sandbox isolation | read/write/exec inside Docker container, not on the worker host |
| LLM + tool use | LLM picks tools → iterates → produces a markdown summary report |
| Architecture | `LLMProvider` / `Tool` / `Sandbox` protocols; implementations are swappable |

## P0 — must implement

1. **Orchestration (thin)**
   - `POST /api/tasks`, `GET /api/tasks/{id}`
   - In-memory queue + single worker; states: `queued → running → succeeded | failed`

2. **Sandbox (thin)**
   - `DockerSandbox`: `create → exec / read / write → destroy`
   - Repo pre-cloned into a named Docker volume; mounted read-only per task
   - Not required: seccomp tuning, GitHub token, remote push

3. **LLM + agent (simple tools; reject out-of-scope ops with clear errors)**

   | Tool | Purpose |
   |------|---------|
   | `read` | Read a file from `/workspace/repo` (optional line range) |
   | `write` | Write report to `/workspace/out/`; source files are read-only |
   | `shell` | Read-only analysis: `rg`, `grep`, `find`, `head`, `wc`, `cat`, `git log` |
   | `finish` | Submit the final markdown report and stop |

   **Reject with a clear error message** (no silent failure):
   - `pip install` / `npm install` / build operations
   - `git push`, open PR, modify GitHub
   - Arbitrary user-supplied repo URLs (demo targets vllm only)

   LLM runs in the worker process; `TOGETHER_API_KEY` via env var only.

4. **Architecture (thin)**
   - Three protocols + one implementation each; no need to match skeleton.py line-for-line

5. **Minimal frontend**
   - Single page: input prompt → submit → poll status → show markdown result
   - No login, no design system; plain HTML acceptable

6. **Demo scenario**
   - Fixed repo: `https://github.com/vllm-project/vllm` (shallow clone, no token)
   - Default prompt: find all TODO/FIXME, summarise in markdown
   - Agent must search with `rg`/`grep` first; must not dump entire repo into context

7. **Acceptance**
   - Frontend or `scripts/demo.sh` exercises the same API end-to-end
   - `ACCEPTANCE.md` is repeatable

## P1 — out of scope for MVP

- SQLite/Redis, multi-worker, multi-tenant, Plan persistence
- Policy engine, LangSmith, Firecracker, Kubernetes
- User-selectable repos, private repos, push/PR, in-sandbox `pip install`
